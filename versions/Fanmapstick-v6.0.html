Accessibility

  • For screen reader users I apologize but unfortunately I do not believe you will find much use in this web toy. This is primarily a 3d render engine and I don't yet have a way for a screen reader to interpret the data on screen. I have looked into how some screen reader users are making accessibility tools for 3d render engines but it is going to take a while to implement fully. If you do find a way to make use of this app it would bring me great joy if you were to email me and let me know. If you're interested in using this web toy and want to help contribute to its screen reader accessibility then I would also appreciate your help. My email for this project is fanmapstick@gmail.com.
  • For everyone else I want to say how much I prize accessibility for all. Having lived with both physical and mental health issues for most of my life and only recently having been diagnosed with a mix of neurodivergencies I know what it's like to deal with something I want to interact with but can't make do. I have had that lens on the whole time as I made the project work and so I hopefully have made it intuitive and easily usable to most people. That said, if you find any issues that hinder your ability to interact with this app please feel free to email me at, fanmapstick@gmail.com, or you can post an issue on github and I will try and fix it.
  • By default this app will allow full control with either the mouse or the keyboard and anything in-between. The keybind menu is meant to accept inputs from any device so I hope this will allow those with alternative input devices to make use of this app. In the future I will be adding pre-built support for other devices such as gamepads, laptop track pads, and touch screen devices.
  • My next big assistance project was to make every setting I could user-adjustable. This includes the colors, sizes, default settings, and much else for every part of the UI. I tried to set it up so that the average user wouldn't have to touch this to get working but so that anyone can make tweaks to increase their ease of use. Paired with this is the ability to export/save, and import control schemas with the ability to link your hotkey bindings to it. So if you want to update to a future version or want to share your setup with a friend it should be no problem.
  • In the same vein but not yet implemented I'm working on a colorblind menu that will allow you to adjust what colors you see for the items on the map. You will also be able to print out the map with the original color and or with the shifted color values. This works by displaying each color used by installed theme items and shifting their color while preserving the base value and each color picker comes with the name of the color and what item(s) it represents so that you know what you're adjusting.
  • I see no current need for sound in this app so you don't need to worry about not being able to hear any kind of indicator or such. If you feel there are legitimate times that a sound cue would be helpful please email me at, fanmapstick@gmail.com, and I'll evaluate the use case. I guarantee I will never make sound a necessity to navigate this app. Any sounds will be able to be modified in the settings menu.

If you need vision correction or assistance then please use the slider at the bottom of this page to change the rest of the font on this page. Or you can click this toggle on which will double the base UI size. Further adjustments can be made in the control schema tab of the user context page. You can navigate to that page once you exit this one by clicking on the question mark in the top right corner of the view port.

What and Why

This project was made with AI coding which I know is a very polarizing topic but I hope you will at least finish reading this section before you dismiss it. And you will see in the next section the data(I say that loosely as I have dyscalculia and am relying on some gathered data collated by the AI.) that shows that this is going to in the long run break even over the input used to generate AI images.

If you skipped the introduction in the accessibility section above then you'll be missing some key info. I have several neurodivergencies and AI has been able to act as an assistive device for me in places where I struggle. I whole heartedly believe that misused AI can be very dangerous and that there should be major restrictions on data centers.

It does make me ashamed to know I'm contributing however little to these places which hurt the life of other people but if I didn't use AI I would be hurting myself as well. So I hope you can forgive me.

This is an extremely light weight 3d rendering engine with many settings to allow you to create random and editable maps for all your tabletop gaming needs. I will get to why I created this in a minute but I've tried to keep down the processing costs to create interesting and highly customizable maps.

I do want to make a note here that I didn't simply say to claude to make this and then let it go, I've spent several weeks of hyperfixation testing and fixing and redoing sections until this has become a fairly well working machine.

I also feel compelled to mention I have spent hundreds and hundreds of hours trying to learn how to code because I find the medium so appealing but with my working memory issues it quickly becomes an agonizing process for me that ends in bad places. I would love to have made this fully by hand but after six years of having the idea and getting ready to start up my dream campaign I decided I needed to get it out there.

I also don't make this to put artists out of a job but to hopefully also reduce the number of people generating AI images to get cool maps to use. I would if I had the spare money laying around have simply paid a programmer to make this for me but I simply don't have that kind of money.

There are a few reasons I made this web toy and they all stem from issues I've run into over my many years of playing tabletop games.

The first issue is that with many modern tabletop games and especially Dungeons and Dragons, combat quickly becomes a slog and I've heard complaints about this brought up over and over again. My hypothesis for why this happens is because during combat you end up giving up on planning your turn ahead because the DM makes you negotiate every tactical advantage which slows things down and makes it hard to predict where you're going to end up which kills not just the tactical vibe but probably your wizard as well, or you have to deliberately do dumb stuff just to keep the game rolling.

This also causes the game to be harder to balance and favors the single huge battle a session dynamic because it becomes harder to balance the combat with many enemies as well as spell effects when the players give up on tactical planning. My hope is to provide not just maps but premade rules which can help players make tactical decisions when it's not their turn so as to help increase attention and keep the game flowing.

The second issue I've run into is the repetitive use of simple maps that don't provide new and interesting scenes for the players which again stifles the tactical decision making even more.

This is no shot against any of my DMs but I have had three different DMs find and use(multiple times) the same basic map they found on google. Thus seeing a map I remember from playing three years ago just makes it feel fake and it's even worse when we spend every session traveling across the continent only to do every battle on the same map that the DM found two months ago. I want this to be a way to instantly create a battlemap with the information needed to make tactical choices and present interesting situations but I got ambitious and made it into its own dedicated map maker with a ton of features and many more to come.

Power and processing use

Now, they are by no means perfect but below is a small collection of data analysis tools to help you see my point. Feel free to read it and play with it to see what is what but I'll summarize the intent behind it.

Going based off what data I could collect from various research papers and the profiling tool I used on this web toy I put this data together which shows that yes AI images can be cheaper for smaller images with the most efficient models but in most cases the processing and power use cost per image is much higher than with my app.

The chart axis never changes with the slider: linear runs 0 to 500 Wh, logarithmic runs 0.001 to 1000 Wh.
